## Key Findings

1. **Data quality issue**: btcusdt_1h_deep.csv only has data from 2021-03-22, not from 2018 as expected (~64k rows vs actual 43,788 rows)

2. **Trade sparsity**: Strategy produces only 22 trades across 3 windows - far below 200 minimum. Volatility expansion events are rare.

3. **Extreme instability**: Window 2 (Aug-Sep 2021) had catastrophic failure with Sharpe -5.3, -8.82% return, -9.55% drawdown

4. **Parameter stability**: Some consistency observed - atr_period=10 stable, contraction_pct~27%, ema_slow~53

## Lessons Learned

1. **volatility_regime.py on BTC produces too few trades** - only enters on rare volatility expansion events after contraction periods

2. **Limited data range (2021-2026) severely constrains WFA** - only 3 windows possible with 3-month training / 1-month testing

3. **ATR-based conviction filtering alone does NOT improve** over EMA Trend Gate baseline - both achieve ~60-67% positive windows but negative aggregate Sharpe

4. **Strategy needs additional filters or parameters** to increase trade frequency and reduce regime sensitivity

## Recommendations

1. **Fix data source**: Verify btcusdt_1h_deep.csv has full historical data or fetch fresh from Binance with complete 2018-present history

2. **Increase trade frequency**: Consider wider parameter ranges for contraction detection or add additional entry conditions

3. **Test alternative assets**: Try ETH or SOL which may have more volatility expansion events

4. **Add risk controls**: Position sizing or regime-based exposure to reduce catastrophic drawdowns in adverse regimes
